# Release v0.1.13

## Highlights

- **Agentic digital identity direction**: README, MkDocs, roadmap, and runtime templates now frame G-Agent as an agentic character runtime for memory, visual identity, legacy, relationships, and owner-controlled workflows.
- **Core cleanup**: Feishu/Lark was removed from the core runtime, config schema, security audit, tests, and dependency lockfile.
- **Simpler deployment surface**: Arch and Debian installers were replaced with one Linux installer that auto-detects common package managers.

## Improvements

- Added `deploy/linux/install.sh` and `deploy/linux/uninstall.sh`.
- Simplified install docs to Linux, macOS, and Windows.
- Reworked README into a concise product front door and moved setup detail into MkDocs.
- Rewrote roadmap around character depth, owner-reviewed learning, session recall, skills as procedural memory, routines, and execution backends.
- Refreshed MkDocs homepage, persona docs, FAQ, security docs, operations docs, and channel docs.
- Replaced the stale Clawra implementation blueprint with a short archive pointer to current docs.
- Updated runtime package metadata from assistant/chatbot framing to agentic digital identity framing.

## Fixes

- Corrected Email docs to use the real default subject prefix (`Re: `).
- Corrected Slack docs to use `dm.enabled=false` for disabled DMs instead of a nonexistent `dm.policy=disabled`.
- Corrected Getting Started docs that referenced a nonexistent systemd template directory.
- Clarified that `g-agent channels login` is for WhatsApp QR login, while Telegram uses token plus sender allowlist.
- Removed stale public references to split Arch/Debian install paths.

## Notes

- Docker/Daytona-style execution environments remain roadmap items for sandboxed or remote work, not install paths.
- Slack remains available but is not part of the primary public channel promise.
