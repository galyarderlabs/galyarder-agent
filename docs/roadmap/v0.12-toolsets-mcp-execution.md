# v0.12: Toolsets, MCP, And Execution Backends

## Goal

Make tools safer and more modular without bloating the core.

## Scope

- Group tools by capability.
- Upgrade MCP configs and runtime behavior.
- Refactor subagents around a shared runner.
- Add execution backend strategy.

## Toolsets

- safe

- messaging

- skills
- routines
- MCP
- code execution
- subagents

## MCP Upgrades

- stdio and HTTP/SSE configs
- schema normalization
- per-tool timeouts
- transient retry
- OAuth only when needed
- path traversal checks

## Execution Backends

- local default
- Docker sandbox for risky tasks
- SSH/VPS for always-on deployment
- advanced backends later only when demanded

## Acceptance Criteria

- Tool exposure can be limited by toolset.
- MCP tools have timeouts and transient retry.
- Subagents support cancellation and status events.
- Completion summaries route back to the origin channel.
- Docker sandbox is optional, not a requirement for local default.

## Agent Handoff

### Current G-Agent State

- `ToolRegistry` is flat.
- `AgentLoop._register_default_tools()` registers all default tools directly.
- `tool_policy`, `risky_tools`, and `approval_mode` exist.
- `SubagentManager` and `SpawnTool` exist.
- There is no first-class MCP client in G-Agent.
- `ExecTool` supports workspace restriction and `allowed_dirs`.

### Implementation Strategy

Add toolsets before adding MCP/backends. Toolsets give a safety boundary that
MCP, subagents, routines, and Web UI can reuse.

Recommended shape:

- `agent/tools/toolsets.py`: tool grouping and selection.
- `agent/tools/mcp.py`: MCP wrappers after toolsets exist.
- `execution/base.py`, `execution/local.py`, `execution/docker.py`: backend
  interface and implementations.
- `agent/runner.py`: shared runner extracted later from `AgentLoop`.

### Implementation Slices

1. Add toolset metadata.
   - safe, file, terminal, web, browser, vision, image, messaging, memory,
     skills, routines, MCP, subagents.
2. Allow runtime to expose a subset of tools.
   - Per character/profile later.
   - Per routine sooner.
3. Add MCP config schema.
   - stdio and URL transports.
   - enabled tools.
   - timeout.
4. Port MCP wrapper from Nanobot carefully.
   - schema normalization
   - per-tool timeout
   - transient retry
   - protocol pollution hints
5. Add Docker execution backend.
   - Keep local default.
   - Docker only for configured risky workflows.
6. Refactor subagent runner after tests exist.

### Guardrails

- Do not expose all MCP tools by default.
- Do not allow MCP path traversal.
- Do not make Docker mandatory.
- Do not refactor the whole agent loop before toolset tests exist.

### First PR Boundary

Toolset registry + tests + per-run tool filtering. MCP comes after.
