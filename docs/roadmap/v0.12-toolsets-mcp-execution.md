## Agent Handoff

### Current G-Agent State

- `ToolRegistry` remains the low-level registry, but `ToolsetResolver` now
  groups registered tools into capability bundles plus dynamic MCP prefix
  groups.
- `AgentLoop._get_effective_tools()` resolves per-message `toolsets` and
  `allowed_tools`.
- `tool_policy`, `risky_tools`, and `approval_mode` exist.
- `SubagentManager`, `SpawnTool`, and `AgentRunner` exist.
- `MCPManager` connects stdio and SSE servers, wraps remote tools, normalizes
  schemas, and retries transient connection failures.
- `ExecTool` uses `LocalEnvironment` and supports workspace restriction plus
  `allowed_dirs`.
- Missing pieces: streamable HTTP MCP transport, Docker execution backend, and
  per-profile toolset policy.

### Implementation Strategy

Add toolsets before adding MCP/backends. Toolsets give a safety boundary that
MCP, subagents, routines, and Web UI can reuse.

Recommended shape:

- `agent/tools/toolsets.py`: tool grouping and selection.
- `mcp/manager.py`: MCP wrappers and connection management.
- `execution/base.py`, `execution/local.py`, `execution/docker.py`: backend
  interface and implementations.
- `agent/runner.py`: shared runner extracted later from `AgentLoop`.

### Implementation Slices

1. Add toolset metadata.
   - safe, file, terminal, web, browser, vision, image, messaging, memory,
     skills, routines, MCP, subagents.
2. Allow runtime to expose a subset of tools.
   - Per character/profile later.
   - Per routine sooner.
3. Add MCP config schema.
   - stdio and URL transports.
   - enabled tools.
   - timeout.
4. Port MCP wrapper from Nanobot carefully.
   - schema normalization
   - per-tool timeout
   - transient retry
   - protocol pollution hints
5. Add Docker execution backend.
   - Keep local default.
   - Docker only for configured risky workflows.
6. Refactor subagent runner after tests exist.
